# Known issues

Known bugs and limitations of the Go backend. New issues are appended with the
next number; the Status column is updated when one is fixed.

Status: `Open`, `Fixed (<version>)`, `Wontfix`.

| # | Description | Status |
|---|-------------|--------|
| 1 | The C runtime cannot PER-encode a present value of `INTEGER (0..18446744073709551615)`: it keeps constraint bounds in a `long`, so even 0 fails ("aper encode failed"). `converter-example` fails identically, and the Go `Encode` returns the same error. Ranges that stay within `long` but exceed 32 bits (e.g. `0..1099511627775`) work. | Open (C runtime) |
| 2 | The generated C constraint check for an `INTEGER_t` beyond `long` uses `asn_INTEGER2long`, so values >= 2^63 are rejected ("value too large"); it also triggers a `-Wsign-compare` warning. | Open (C generator) |
| 3 | Type names that exist in several modules of one `-Fgo` run (the same name in two input files) make the generated conversion code refer to `struct <Name>` instead of the module-prefixed C name, so the cgo package fails to compile (`invalid application of 'sizeof' to incomplete type`). Workaround: give the types unique names. | Fixed (go.7) |
| 4 | A field of an inline `SEQUENCE` was checked for name collisions against the fields of the enclosing struct, so valid specifications (e.g. `examples/rrc-7.1.0.asn1`'s `completeSIB-List`) were refused. Output was never wrong. `rrc-7.1.0.asn1` now stops at #16. | Fixed (go.7) |
| 5 | `SEQUENCE OF` an inline unsigned `INTEGER` wider than 32 bits is not supported as an element (`INTEGER (0..4294967295)`): the C generator emits unusable C (`asn_DEF_Member_2` undeclared). | Fixed (go.7) |
| 6 | `SEQUENCE OF SEQUENCE OF {SEQUENCE \| CHOICE}` (and the `SET OF` forms): the C generator emitted unusable C. The Go backend handles both the `SEQUENCE OF` and the `SET OF` forms. | Fixed (go.7) |
| 7 | `SEQUENCE OF` a reference to a NULL type fails with `asn1cgo: conv: unresolved seqof elem`. | Fixed (go.7) |
| 8 | `SEQUENCE OF` with a `SIZE` constraint on both the outer and inner list makes asn1c abort in the parser (`asn1p_y.y` assertion). | Fixed (go.7) |
| 9 | `ISO646String` makes asn1c abort (`asn1fix_constraint_compat.c`, `asn1constraint_default_alphabet` assertion). | Open (asn1fix) |
| 10 | A top-level wide `INTEGER_t` leaf is always converted with the unsigned verbs, even when its Go type is `int64`. Only reachable with `-fwide-types`. | Open |
| 11 | An empty `PrintableString` (no `SIZE` lower bound) fails `Encode` with "value not given": the C constraint function rejects the NULL buffer an empty Go string produces. The other restricted string types allocate the buffer and are not affected. | Fixed (go.7) |
| 12 | A `DEFAULT` on a `BMPString` or `UniversalString` member was refused: the C generator stored the default as single-byte characters, not UCS-2 / UCS-4. The C generator now converts the quoted literal (UTF-8 in the specification file) to UCS-2 / UCS-4 big-endian; a character that does not fit or invalid UTF-8 stops generation with an error naming the member. The member is a plain `string` in Go. | Fixed (go.9) |
| 13 | The C time check accepts text after a well-formed `UTCTime` / `GeneralizedTime` (`"250102030405ZZ"`); the Go side does not parse or normalize time strings. | Open (C runtime) |
| 14 | `GeneralString`, `GraphicString`, `TeletexString`, `T61String` and `VideotexString` are written and read as hex in XER by the C runtime (it does not decode their character sets). The Go value is the raw bytes. | Open (C runtime) |
| 15 | The C runtime's XER decoder cannot read an empty `RELATIVE-OID` (`<x></x>`), although its XER encoder writes one; the APER of such a value round-trips. `converter-example -ixer` fails with "Input processing error". | Open (C runtime) |
| 16 | `examples/rrc-7.1.0.asn1` stopped at an enumerator name collision: in `SFN-SFN-Drift` the enumerators `sfnsfndrift5` and `sfnsfndrift-5` (and 13 more such pairs) both mapped to `SFNSFNDriftSfnsfndrift5`. Within one enumerator or named-bit list, a member that clashes with a sibling and has `_<digit>` in its C name now keeps that underscore (`D1` / `D_1`). | Fixed (go.8) |
| 17 | A `DEFAULT` on a `UTF8String`, `GeneralString`, `GraphicString`, `TeletexString`, `T61String`, `VideotexString`, `ObjectDescriptor`, `UTCTime` or `GeneralizedTime` member was refused: the C generator emitted no default callbacks for these types (the member was always encoded and NULL when absent), and the Go refusal wrongly said that character strings in general have no DEFAULT support. The C generator now accepts a quoted-string DEFAULT for every character string and time type and stores the bytes of the literal as written (UTF-8 for `UTF8String`). The time syntax of the literal is not checked by the generator; an invalid one is stored as is, decoding fills it in, and the runtime constraint check then rejects the value. The member is a plain `string` in Go. | Fixed (go.9) |
| 18 | The same hyphen clash on SEQUENCE fields, CHOICE alternatives, type names and typed value names (`T ::= SEQUENCE { a1 BOOLEAN, a-1 BOOLEAN }`, `T1` / `T-1`) was refused with a collision. Within one sibling list (or one module, for type and value names) the member with `_<digit>` in its C name that clashes now keeps the underscore (`A1`, `A_1`; `TA_1` for an inline type, `TPrA_1` for the choice constant, `T_1` for a type); names that do not clash are unchanged. | Fixed (go.8) |
| 19 | On a large specification (`examples/rrc-7.1.0.asn1`, about 4100 layout nodes) `asn1c -Fgo` ran for over ten minutes: the glue emitter and the package orderer searched all nodes, name rows or header files for every type, and appended to the generated files with a `strlen` of the whole file each time. The lookups are now indexed and the generated files are built in a length-tracking buffer; output is byte-identical and the run takes about 40 s. | Fixed (go.8) |
| 20 | With `-findirect-choice`, a member or alternative whose type is an alias of an alias (`PFL ::= Freq`, `pf PFL OPTIONAL`) was declared `struct PFL *pf;`, but no `struct PFL` exists (`PFL.h` has only `typedef Freq_t PFL_t;`): plain C code could not use the member, and the Go converters failed with `sizeof` of an incomplete type (`MBMS-PFLInfo ::= FrequencyInfo` in `rrc-7.1.0.asn1`). The C generator now names the constructed type the alias chain ends in (`struct Freq *pf;`). | Fixed (go.8) |
| 21 | A top-level alias of a CHOICE (`Alias ::= Orig`, also an alias of an alias) generated converters that spelled the alias's own C names, `Alias_PR`, `Alias_PR_t1` and `struct Alias__t2`; C has only `typedef Orig_t Alias_t;`, so the cgo build failed (`RLC-PDU-Size ::= OctetModeRLC-SizeInfoType1` in `rrc-7.1.0.asn1`). The converters now use the C names of the CHOICE the alias chain ends in (`Orig_PR`, `struct Orig__t2`, also for nested CHOICE, SEQUENCE OF and SEQUENCE alternatives); the Go types and converter names are unchanged. | Fixed (go.8) |
| 22 | A CHOICE alternative named after a C reserved word (`explicit`, `int`, `auto`, `default`, `struct`) failed the cgo build: asn1c upper-cases the first letter of such a union member (`C.h` has `Explicit`), but the converters wrote `choice.explicit` and, for the flat slot, `out->struct` (`HARQ-Info.memoryPartitioning` in `rrc-7.1.0.asn1`). The converters now use the upper-cased member for the union and the flat slot and keep the lower-case `_PR` constant (`C_PR_explicit`); the Go names are unchanged. | Fixed (go.8) |
| 23 | A named `SEQUENCE OF` imported from another module (`l ItemList` with `IMPORTS ItemList FROM ModA`) made the importing package's `glue.go` spell the type `moda.moda.ItemList` (a syntax error); inside the owning package the same bug wrote a self-qualified name (`informationelements.DLAddReconfTransChInfoList`). The spelling is taken from the referencing field, which can already carry a package qualifier; it is now stripped before qualifying for the package being emitted. | Fixed (go.8) |
| 24 | An OPTIONAL member whose type is an alias of a named `SEQUENCE OF` (`Li ::= SEQUENCE OF It`, `BLi ::= Li`, `b BLi OPTIONAL`) is declared `struct Li *b` in C; encoding a Go value with it present hangs in the C encoder (the C converter encodes the same value fine). Workaround: use the list type itself for the member. | Open |
| 25 | A SET member governed by an information object class open type (`value IE-CLASS.&Value ({Msg-IEs}{@id})` inside `SET { ... }`) is refused. The C generator types such a member as `ANY_t` and emits no `<T>_<m>_PR` union or open-type decoder, so there is nothing for the Go side to mirror. SEQUENCE keeps working. | Open (C generator) |
| 26 | A SEQUENCE with two or more inline `CHOICE` members (`T ::= SEQUENCE { m CHOICE {...}, p CHOICE {...} }`) failed the cgo build of the generated glue (`no new variables on left side of :=`, `cannot use *&v.P ... as TM value`): the value variable of each inline CHOICE was declared at function scope, so the second one reused the first. Each inline CHOICE now has its own block scope in the fill and size code. `examples/rrc-7.1.0.asn1` (`UE-Positioning-OTDOA-NeighbourCellInfo`) gets past this. | Fixed (go.8) |
| 27 | A CHOICE alternative that is an empty inline `SEQUENCE {}` (`CHOICE { e SEQUENCE {}, k BOOLEAN }`) failed at run time: `Encode` panicked (`index out of range` in `allocStruct`) and `Decode` returned E_ALLOC. | Fixed (go.8) |
| 28 | A `BIT STRING` member (plain, DEFAULT, or inside a `SEQUENCE OF`, inline or named) of a type imported from another module failed the build when the importing package declares a BIT STRING of its own: every package has its own `BitString` struct, and the importing glue spelled the imported value with its local one (`cannot use v.Bm (variable of struct type moda.BitString) as BitString value in argument to writeBitsField`, `cannot use v.L (variable of slice type moda.SPL) as []BitString value`). A BitString value is now spelled with its owner module's type, with a Go conversion where the local helpers take their own type. `examples/rrc-7.1.0.asn1` (`SynchronisationParameters-r4`) gets past this. | Fixed (go.8) |
| 29 | Two more spellings in the glue of a package that uses a type imported from another module were not package-qualified, so the build failed: an OPTIONAL member whose type is a named `BIT STRING` (`undefined: BitString` when the importing package declares no BIT STRING of its own), and an OPTIONAL inline `SEQUENCE OF` member (`undefined: SPL`, the list type of the owner). Both are now spelled with the owner's package, and a package with no BitString of its own takes the helper type from a package it actually imports. `examples/rrc-7.1.0.asn1` gets past both. | Fixed (go.8) |
| 30 | `Encode` of a zero-length `BIT STRING` (a plain, OPTIONAL or CHOICE-alternative member, or a `SEQUENCE OF` element) failed with `BIT STRING: value not given`, so a value that `Decode` had produced could not be encoded again. The converter now always gives the C value a buffer. Generated C converters change; regenerate. | Fixed (go.8) |
| 31 | With `-fwide-types`, a REAL member narrowed to a C `float` by `WITH COMPONENTS { mantissa (-16777215..16777215), base (2), exponent (-100..100) }` (X.696 12.2) does not compile: its header includes `REAL.h` but the descriptor uses `NativeReal` (`unknown type name asn_NativeReal_specifics_t`). Independent of DEFAULT. | Open (C generator) |
| 32 | A `float` REAL member (see #31, without `-fwide-types`) of a SEQUENCE is described by the generic `asn_DEF_NativeReal` (the per-member descriptor with the float size is generated but not used), so the runtime reads and writes 8 bytes through a 4-byte member: AddressSanitizer reports a heap-buffer-overflow in `NativeReal__get_double` when such a member is encoded, and the aligned PER codec reads a `double` directly. Only the `DEFAULT` callbacks of such a member are correct (they store and compare a `float`). Independent of DEFAULT. | Open (C generator / runtime) |
| 33 | A REAL `DEFAULT` given as `{ mantissa M, base B, exponent E }` is refused by the C generator (no default callbacks) and by the Go backend; use a decimal number or `PLUS-INFINITY`, `MINUS-INFINITY`, `NOT-A-NUMBER`. | Open (C generator) |
| 34 | A `DEFAULT` on a named-bit `BIT STRING` member (`{ p, q }`, `{ }`, `'01'B`) or on an `OBJECT IDENTIFIER` / `RELATIVE-OID` member (`{ 1 3 6 }`, `{ iso(1) 3 6 }`) was refused: the C generator emitted no default callbacks for them, so a decoder left an absent member empty and the encoder never omitted one equal to the default. The C generator now emits them (trailing 0 bits of a named-bit value are not significant; the default is padded to the lower bound of a SIZE constraint) and the Go backend accepts them. An unknown bit name, a bare OID name other than the first arc `iso` / `itu-t` / `joint-iso-itu-t`, or arcs no OID can have stop generation. | Fixed (go.9) |
| 35 | After #34, a value reference in the `DEFAULT` of an `OBJECT IDENTIFIER` / `RELATIVE-OID` member (`DEFAULT id-base`, `{ id-base 5 }`, `{ id-base rel-x }`, `{ id-base n(arc-n) }`, also an imported value) stopped generation for every user of the C generator, although such a specification compiled before. The generator now resolves the names (X.680 ObjIdComponents) in the module's namespace; an unknown name, a name of another type or a cycle still stops generation with an error naming the member and the name. | Fixed (go.9) |
| 36 | `h RELATIVE-OID DEFAULT rel-x` (the whole DEFAULT is a reference to a RELATIVE-OID value) is rejected by asn1fix before code generation (rc=65, `Possibly incompatible type of "h" (RELATIVE-OID) ... with "rel-x" (RELATIVE-OID)`): `asn1f_check_value_type` (`libasn1fix/asn1fix_value.c`) ignores the type mismatch warning for OBJECT IDENTIFIER only, not for RELATIVE-OID. Present in every version. Workaround: `DEFAULT { rel-x }`. | Open (asn1fix) |
